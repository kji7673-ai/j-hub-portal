# 📚 J-Hub (진양저널) 사내 포털 개발 실전 매뉴얼
<!-- 작성일: 2026-07-18 | 버전: v1 -->

> [!NOTE]
> **과정 개요 및 목표**  
> 본 매뉴얼은 진양 엔지니어링 건축사 사무소의 핵심 사내 포털인 **'J-Hub(진양저널)'**을 백지상태에서 다시 구축한다고 가정할 때, 어떤 순서와 기술로 접근해야 하는지 정리한 실무 교육 자료입니다. 
> 
> 과거에는 파편화된 파일 교환과 수동 업데이트로 인해 정보 누락(예: [A구역] 검토 내용 유실)이 빈번했으나, 이 포털 도입을 통해 **오프라인 환경에서도 작동하는 무중단 사내 지식 베이스**를 구축하는 과정을 스토리텔링 방식으로 풀어냅니다.

---

## 1. 🏗️ 사전 준비 및 환경 구성

작업을 시작하기 전, J-Hub의 뼈대를 이루는 폴더 계층 구조를 먼저 구성합니다.

```text
j-hub-portal/
├── app.py                  # 백엔드 서버 구동 및 로그인 API 처리
├── index.html              # 프론트엔드 메인 UI 화면
├── sw.js                   # 오프라인 지원을 위한 Service Worker
├── js/
│   └── workspace.js        # 프론트엔드 동적 렌더링 로직
├── data/
│   └── workspace.json      # 지식 베이스 및 리포트 데이터
└── _dev_tools/             # 개발 간 생성된 유지보수용 스크립트 보관
```

**[환경 복사 방식 안내]**
1. 기존 `[B프로젝트]` 템플릿 폴더를 통째로 복사해옵니다.
2. 터미널(명령 프롬프트)에서 해당 폴더로 진입 후, 가상환경을 활성화하고 `pip install -r requirements.txt`로 의존성을 설치합니다.

## 2. 🗺️ 개발 흐름도 (Process Flow)

J-Hub 개발은 크게 4단계로 진행됩니다: **① 화면 설계 ➔ ② 인증(보안) 구현 ➔ ③ 데이터 렌더링 ➔ ④ 오프라인 최적화**.

```mermaid
flowchart TD
    A([프로젝트 시작]) --> B[index.html 화면 레이아웃 구성]
    B --> C{보안 및 로그인 구현}
    C -->|Flask 서버| D[app.py API 설계]
    C -->|클라이언트| E[localStorage 오프라인 저장]
    D --> F[workspace.json 데이터 연동]
    E --> F
    F --> G[Service Worker (sw.js) 등록]
    G --> H([최종 배포 및 구동])
    
    style A fill:#0066cc,stroke:#fff,color:#fff
    style H fill:#00cc66,stroke:#fff,color:#fff
```

> [!TIP]
> **필수 용어 해설**
> - **API (Application Programming Interface)**: 클라이언트(웹 브라우저)와 서버(app.py)가 데이터를 주고받기 위한 소통 창구. (예: `/api/login`)
> - **localStorage**: 웹 브라우저가 사용자 기기 내부에 데이터를 임시로 저장하는 창고. 서버가 꺼져도 로그인 세션을 유지하는 데 쓰입니다.
> - **Service Worker (sw.js)**: 웹 페이지 백그라운드에서 실행되는 스크립트로, 오프라인 상태에서도 화면(HTML, CSS)을 보여줄 수 있도록 캐시(Cache)를 관리합니다.

## 3. 📸 단계별 구현 내용 및 시각적 삽도

### 1단계: 메인 대시보드 및 로그인 인터페이스
가장 먼저 사용자를 맞이하는 로그인 화면과 로그인 성공 직후의 대시보드 구조를 짭니다. 이때 XSS 공격을 방어하기 위한 텍스트 정제(Sanitization) 로직이 필수입니다.



> [!IMPORTANT]
> - 입력 폼 생성 시 텍스트 필드 값은 반드시 특수문자를 걸러내야 합니다.
> - **프롬프트 실전 예시**: `"AI야, 로그인 화면 폼을 만들건데 사용자가 악성 자바스크립트를 입력하지 못하도록 sanitizeHTML 함수를 적용해서 XSS 방어 로직을 추가해줘."`

### 2단계: 모자이크(Mosaic) UI 및 지식 베이스 열람
진양저널의 핵심인 주간 보고서와 실무 지식을 열람하는 뷰어 화면입니다. 서버 API에서 받아온 `[ID-a8f9]` 번호 등 고유 식별자를 통해 데이터를 동적으로 아코디언(Accordion) UI에 그려냅니다.



### 3단계: 모바일 반응형 및 편의 기능 (비밀번호 변경 등)
대표이사 및 실무진들이 현장에서 스마트폰으로 접근할 때 깨짐이 없도록 미디어 쿼리(Media Query)를 적용하고, 하단 내비게이션 바에 비밀번호 변경 등 유틸리티 기능을 배치합니다.



> [!CAUTION]
> 비밀번호 처리 시 절대 평문으로 저장해서는 안 됩니다.
> - **프롬프트 실전 예시**: `"비밀번호 변경 기능을 추가하려고 해. 사용자가 0000과 같은 새 비밀번호를 입력하면, 클라이언트에서는 그대로 보내되 서버단(app.py)에서 반드시 SHA-256으로 해싱해서 검증하고 저장하도록 해줘."`

## 4. ✅ J-Hub 개발 10대 핵심 체크리스트 (해야 할 일)

향후 동일한 성격의 사내 포털을 구축할 경우, 아래 10가지 작업을 순서대로 완수해야 합니다.

1. `[ ]` **정적 리소스 준비**: `index.html` 뼈대 작성 및 `Apple-design-analysis` 룰셋 적용 (SF Pro, -0.37px 자간 등)
2. `[ ]` **데이터 설계**: `workspace.json` 규격 확립 및 목업 데이터 삽입
3. `[ ]` **서버 구동 (Flask)**: `app.py` 초기화 및 정적 파일 서빙 세팅
4. `[ ]` **보안 난수 적용**: `app.secret_key`에 `os.urandom(32).hex()` 적용
5. `[ ]` **인증 체계 구축**: `/api/login` 엔드포인트와 암호화 해싱 비교 로직 구현
6. `[ ]` **동적 렌더링**: `js/workspace.js` 내에 데이터 루프 렌더링 함수 구현
7. `[ ]` **보안 조치**: 렌더링 시 모든 외부 입력 텍스트에 `sanitizeHTML` 적용
8. `[ ]` **오프라인 Fallback**: 네트워크 장애 시 `localStorage` 로그인 세션 복구 로직 구현
9. `[ ]` **캐싱 (PWA)**: `sw.js` 캐시 버전 관리 및 리소스 강제 캐싱 적용
10. `[ ]` **클라우드 배포**: Render 또는 GitHub Pages 등 외부 망 개통 (GitHub CLI 연동)

---

**[결론 및 효과]**
이러한 체계적인 절차를 밟아 완성된 J-Hub는 현장의 열악한 네트워크 상태에서도 문서를 열람할 수 있으며, 악의적인 코드 주입(XSS)이나 세션 탈취 위험을 근본적으로 차단한 **무결점 지식 경영 시스템**으로 작동하게 됩니다.

## 📌 Part 2: 구축 아키텍처 심화 (기존 SOP 07 내용)

> 이 섹션은 진양 엔지니어링의 정비사업 동향 관리 포털인 **J-Hub (진양저널)**의 데이터 파이프라인 흐름을 이해하고, 새로운 기능 확장을 위한 안내서로 활용할 수 있도록 작성되었습니다.

## 🏗 1. 구축 기획 및 설계 (Architecture & Planning)

J-Hub는 단순한 웹사이트가 아닌 **데이터의 자동 수집, 가공, 렌더링**을 수행하는 하나의 작은 '사내 애플리케이션'입니다. 구축 시 가장 먼저 해야 할 일은 **데이터가 어떻게 흘러가는지(Data Flow)**를 설계하는 것입니다.

### 핵심 시스템 구조
1. **백엔드 (파이프라인 모듈)**: 서울시 API, 네이버 밴드 주간보고서, 신문 기사 등을 스크래핑(크롤링)하여 JSON 파일로 저장합니다.
2. **크론 스케줄러 (Cron)**: 정해진 시간(매일 아침 8시 등)에 백엔드 모듈을 가동하여 데이터를 최신화합니다.
3. **빌드 엔진 (build_jhub.py)**: Python 스크립트가 여러 HTML 컴포넌트를 조립하여 최종 `index.html`을 구워냅니다(Static Site Generation 방식).
4. **프론트엔드 (UI/UX)**: 사용자에게 보여지는 화면으로, 애플 특유의 정갈한 디자인 토큰(SF Pro, 여백 중심 등)을 적용합니다.

---

## 🚀 2. 단계별 구축 순서 (Step-by-Step)

### Step 1. 프론트엔드 기초(디자인 시스템) 수립
- **작업**: 색상(Action Blue, Parchment), 타이포그래피(SF Pro Display/Text), 공통 컴포넌트(버튼, 칩, 모자이크 그리드 등)를 정의하는 `styles.css`를 먼저 작성합니다.
- **목표**: 일관된 룩앤필(Look and Feel) 유지.

### Step 2. 백엔드 크롤러 개발 (데이터 수집)
- **작업**: 각 출처에서 데이터를 모아오는 파이썬 스크립트를 작성합니다.
    - `fetch_seoul_notices.py`: 서울시 열린데이터광장 OpenAPI 연동
    - `fetch_band_reports.py`: 직원들의 주간 업무보고 텍스트 수집
    - `pipeline_daily.py`: 언론사 RSS 또는 포털 뉴스 크롤링

### Step 3. 통합 데이터 파이프라인(JSON) 구성
- **작업**: 스크립트들이 가져온 이질적인 데이터를 하나의 `workspace.json` 및 `articles.js` 포맷으로 규격화합니다. 
- **설명**: 프론트엔드가 이 파일만 읽으면 화면을 그릴 수 있도록, 서버리스(Serverless) 형태로 구축합니다.

### Step 4. 빌드 스크립트 작성 (`build_jhub.py`)
- **작업**: 헤더, 사이드바, 각 페이지(대시보드, 캘린더 등)의 조각난 HTML을 하나로 합쳐 완벽하게 동작하는 `index.html`을 생성하는 코드를 만듭니다.

### Step 5. 스케줄링 등록 (자동화)
- **작업**: 쉘 스크립트(`run_daily_sync.sh`)를 작성하고, `crontab`을 통해 맥(Mac)이나 리눅스 서버에서 매일 자동으로 쉘 스크립트를 실행하도록 예약합니다.

## 🛠 4. 향후 확장 및 실무 교훈 (Lessons Learned)

J-Hub를 직접 구축하며 얻은 중요한 기술적 교훈은 다음과 같습니다.

1. **외부 의존성에 대한 안전망(Fallback)**: 크롤링 중 네트워크가 끊기거나 라이브러리(`beautifulsoup4` 등)가 설치되어 있지 않을 때 스크립트가 죽지 않고 안전한 가짜 데이터(Mock data)로 우회하도록 코드를 작성해야 합니다.
2. **동적 렌더링의 분리**: 수시로 내용이 바뀌는 `수집 완료 시각`이나 `주차 라벨`은 HTML에 박아두는(Hardcoding) 대신, 자바스크립트를 이용해 실행 시점에 계산하여 끼워 넣어야 유지보수 비용이 크게 절약됩니다.
3. **에이전트 로그 관리**: 매일 백그라운드에서 크론이 돌 때, 에러가 났는지 정상 작동했는지 파악할 수 있도록 반드시 로그(Log) 파일에 성공 여부와 시각을 기록(`>> sync.log`)해야 합니다.

---

> 💡 **대표이사님을 위한 한 줄 요약**: J-Hub 구축의 핵심은 "사람이 수동으로 문서를 편집하던 행위를 파이썬 봇(Bot)이 대신 하도록 코드를 짜고, 이를 새벽마다 자동으로 실행되게 만드는 것"입니다.
