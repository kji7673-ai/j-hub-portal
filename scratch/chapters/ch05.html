제6장. 시스템 운영 및 출력물 배포 원칙

냉정하게 바라본 우리 시스템의 현주소

대표이사 개인 일기 플랫폼에 기록된 통찰을 바탕으로, 앞으로 진양엔지니어링이 나아가야 할 방향성과 플랫폼 중심의 건축사무소 운영 철학을 공유합니다.

"플랫폼을 통한 설계사무소가 진행되어야 한다."

예전처럼 선배가 후배를 도제식으로 가르치고 개인의 역량에 의존하던 시대는 지났습니다. 이제 설계사무소의 수준과 품질의 유지는, 출력물을 나오게 하는 플랫폼에 대한 공동 관리와 데이터의 축적에 있습니다.

시스템이 품질의 하한선을 완벽하게 방어하고, 파이프라인이 반복적인 업무를 자동화할 때, 우리는 더 높은 차원의 기획과 디자인에 역량을 집중할 수 있습니다. 개인의 암묵지가 아닌, 플랫폼에 축적된 명시적 데이터가 우리 회사의 진짜 자산입니다.

모듈형 엔진과 동적 렌더링 엔진의 차이점 (Q&A)

제22장. 모듈형 엔진과 동적 렌더링 엔진의 차이점 (Q&A)

최근 진양엔지니어링 시스템에 도입된 두 가지 핵심 엔진 개념(모듈 조립과 동적 렌더링)의 차이점과 도입 이유에 대한 문답입니다.

Q. 모듈형 문서 엔진과 동적 렌더링 엔진의 차이가 무엇입니까?

A. 두 엔진은 역할이 완전히 다릅니다.

• 모듈형 엔진 (데이터 조립기): 챕터 1, 챕터 2 등 뿔뿔이 흩어진 텍스트(HTML) 조각들을 레고 블록처럼 모아 하나의 긴 문서로 안전하게 '조립'해 주는 엔진입니다. (Jinja2 기술 사용)

• 동적 렌더링 엔진 (시각화 출력기): 조립이 끝난 문서를 읽고, CSS 디자인을 입히고, 자바스크립트(Mermaid 흐름도 등)를 실행하여 페이지가 넘쳐흐르지 않도록 계산한 뒤 최종 PDF로 '굽는' 엔진입니다. (Headless Chrome 기술 사용)
Q. 각 방식의 장단점은 무엇입니까?

[모듈형 조립 엔진]
• 장점: 부록 중복 오류나 글씨 잘림 같은 물리적 에러가 원천 차단됩니다. 한 챕터만 수정하기 쉽습니다.
• 단점: 초기 세팅(템플릿 구조화)이 복잡하고 손이 많이 갑니다.

[동적 렌더링 엔진]
• 장점: 화면을 브라우저가 직접 그려주므로, 어두운 테마(Dark mode)나 복잡한 다이어그램도 완벽하게 PDF로 출력됩니다. 알아서 줄바꿈(Page break)을 계산합니다.
• 단점: 렌더링을 위해 가상의 크롬(Chrome) 브라우저를 백그라운드에서 띄워야 하므로, 단순 텍스트 변환보다 시스템 리소스(RAM)를 약간 더 소모합니다.
Q. 과거의 정적 변환기를 버리고, 굳이 무거운 '동적 렌더링 엔진'을 도입하게 된 결정적 이유는 무엇입니까?

A. 가장 큰 이유는 '디자인의 진화'와 '자동 줄바꿈 한계' 때문이었습니다.
과거의 정적 텍스트 슬라이싱 방식은 단순히 글자 수를 세서 억지로 상자에 구겨 넣었기 때문에 내용이 넘쳐 사라지는 치명적 오류가 잦았습니다.
또한, 대표이사님께서 도입하신 다크 모드 디자인, Mermaid 흐름도, Apple 스타일의 정밀한 CSS는 일반적인 PDF 변환기로는 흑백의 깨진 글자로만 출력됩니다.
이를 해결하기 위해, '실제 브라우저가 자바스크립트를 모두 실행하고 화면을 완벽히 그린 다음 사진을 찍듯이 PDF로 저장'하도록 하는 동적 렌더링(Headless Chrome) 기술을 도입할 수밖에 없었습니다.

[조직 확장] AI 워크스페이스 완벽 복제 및 인수인계 (Q&A)

제37장. [조직 확장] AI 워크스페이스 완벽 복제 및 인수인계 (Q&A)

조직 확장을 대비하여, 개인의 PC에 구축된 고성능 AI 파이프라인을 신규 입사자에게 100% 동일하게 이식(Clone)하는 방안에 대한 문답입니다.

Q. 내 지식(MD 파일들)만 넘겨주면, 다른 사람도 용문동 보고서를 똑같이 자동 생성할 수 있을까요?

A. 불가능합니다. AGENTS.md나 지식베이스 같은 MD 파일은 AI의 '두뇌(기억과 룰)'일 뿐입니다. AI에게 "용문동 검토해"라고 지시해도, 그것을 물리적으로 그려낼 '근육(코드)'과 공공데이터를 열 '열쇠(API 키)'가 그 사람의 PC에 없다면 AI는 에러를 반환하고 멈춥니다.
Q. 그렇다면 다른 사람이 똑같은 작업을 하려면 구체적으로 무엇을 더 전달해야 합니까?

A. 완벽한 복제를 위해 다음 3대 필수 요소가 함께 전달되어야 합니다.
1. The Engine (스크립트/템플릿): .agents/skills/ 폴더 하위의 파이썬 파일 및 HTML 레이아웃 파일. (렌더링을 수행하는 실체)
2. The Keys (환경변수 및 API 키): VWorld, 국가법령정보 등 데이터를 끌어오기 위한 공용 인증키.
3. The Trigger (최초 기동 프롬프트): 시스템을 로드하기 위해 새 담당자가 AI에게 던져야 하는 정확한 첫 번째 지시어.
[핵심 용어 사전 (Glossary)]
• 환경 이식성 (Environment Portability): 내 컴퓨터에서 돌아가는 자동화 시스템이 남의 컴퓨터에서도 설정 변경 없이 똑같이 돌아가게 만드는 능력.
• 워크스페이스 복제 (Workspace Clone): 파일 몇 개만 메일로 보내는 것이 아니라, .agents/ 숨김 폴더 전체를 Git이나 클라우드로 동기화하여 인프라를 통째로 복사하는 행위.
• 트리거 (Trigger): 스크립트와 MD가 완벽히 세팅된 상태에서, 파이프라인의 폭발을 일으키는 단 하나의 '방아쇠' 문장.

공공 API 직결 및 무인 스케줄링

제38장. 공공 API 직결 및 무인 스케줄링

인터넷 화면을 대충 긁어오면 홈페이지 개편 시 시스템이 멈춥니다. 국가 DB 창고로 직결되는 전용 통로(API)를 뚫어 오류 확률 0%를 보장합니다.

[적용 1] 국가법령정보센터 API (법규 검토)
• 목적: 엑셀에 적힌 구버전 용적률을 적용하는 참사 차단.
• 발급법: open.law.go.kr에서 오픈 API 키 신청.
[적용 2] VWorld 공간정보 API (건축개요)
• 목적: 수십 개 지번을 수기로 치는 휴먼 에러 방지.
• 발급법: vworld.kr 데이터 서비스 인증키 발급.
[무인 스케줄러] LaunchAgent (맥 네이티브)
- 크론탭(Cron)은 컴퓨터가 잠들면 멈추지만, LaunchAgent는 맥을 강제로 깨워(Wake) 실행합니다.

* 구현 방법:
1. ~/Library/LaunchAgents/com.jinyang.plist 생성.
2. StartCalendarInterval을 09시 00분으로 지정.
3. <key>WakeReason</key> 속성을 부여하여 멱살 잡고 기상.
4. launchctl load 로 심장 박동 가동.

무료 웹호스팅 기반 사내 포털 배포 매뉴얼

사내 인트라넷이나 포털을 구축하기 위해서는 보통 서버 임대 비용과 도메인 구매 비용이 발생합니다. 하지만 정적 파일로만 구성된 웹페이지의 경우, 글로벌 플랫폼(GitHub + Vercel)을 활용하면 100% 무료로 초고속 호스팅 환경을 구축할 수 있습니다. 본 매뉴얼은 진양 엔지니어링의 J-Hub 포털을 비용 없이 인터넷에 런칭했던 실제 사례를 바탕으로 작성되었습니다.

1. 사전 준비 및 환경 구성

  • [준비물 1] GitHub 계정: 코드를 무료로 저장할 수 있는 클라우드 저장소
  • [준비물 2] Vercel 계정: GitHub에 저장된 코드를 읽어와 전 세계 인터넷으로 방송(송출)해 주는 무료 호스팅 서비스
  • [작업 폴더]: 작성된 웹사이트 코드 파일(예: index.html)이 특정 폴더에 준비되어 있어야 합니다.
💡 필수 용어 해설
  • 웹 호스팅(Web Hosting): 내 컴퓨터에 있는 파일을 24시간 켜져 있는 거대한 서버 컴퓨터에 빌려 올려두고, 누구나 인터넷 주소로 접속해 볼 수 있게 하는 서비스입니다.
  • GitHub (깃허브): 전 세계 개발자들이 자신의 코드(문서)를 올려두고 보관하는 가장 큰 '소스코드 은행'입니다.
  • Vercel (버셀): 깃허브 창고에 있는 코드를 가져다가 예쁘게 포장해서 빠르고 안정적인 인터넷 주소(URL)로 연결해 주는 자동화 배포 플랫폼입니다.
  • Repository (창고/저장소): 프로젝트 단위로 코드를 보관하는 하나의 폴더 개념입니다.

2. 전체 배포 플로우차트

3. 상세 진행 단계 (Step-by-Step)

STEP 1: GitHub에 빈 창고(Repository) 만들기

가장 먼저 우리가 만든 index.html 파일을 보관할 빈 창고를 만들어야 합니다.

  1. GitHub에 로그인한 뒤, 상단의 초록색 New 버튼을 클릭합니다.
  2. 창고 이름(Repository name)에 j-hub-portal과 같이 원하는 이름을 영어로 입력합니다.
  3. 스크롤을 내려 맨 아래 초록색 Create repository 버튼을 클릭합니다.
STEP 2: 파일 업로드하기 (Drag & Drop)

빈 창고가 생성되면, 파일을 올릴 수 있는 화면이 나타납니다.

  1. 화면 중간의 하늘색 박스 안에 있는 파란색 글씨 uploading an existing file을 클릭합니다.
  2. 점선으로 된 큰 네모 칸이 나오면, 내 컴퓨터에 있는 index.html 파일을 마우스로 끌어다 놓습니다.
  3. 업로드가 완료되면 하단의 초록색 Commit changes 버튼을 눌러 저장합니다.
STEP 3: Vercel 계정 연동 및 배포 권한 부여

GitHub에 파일이 잘 저장되었다면, 이제 Vercel을 통해 인터넷 주소를 만들 차례입니다.

  1. Vercel 메인 화면에서 Continue with GitHub 까만색 버튼을 클릭합니다.
  2. Vercel이 GitHub 창고를 들여다볼 수 있도록 Install 또는 Authorize 버튼을 눌러 권한을 허락합니다.
  3. 주의: 중간에 Secure Your Account with 2FA 화면이 나오면, 하단 Skip securing my account를 눌러 건너뛸 수 있습니다.
STEP 4: 최종 배포 (Deploy) 및 URL 획득

권한 연동이 끝나면 메인 대시보드로 이동합니다.

  1. Deploy your first project 항목 첫 번째에 방금 만든 창고(예: j-hub-portal)가 표시됩니다.
  2. 우측 파란색 Import 버튼을 클릭합니다.
  3. 이어지는 설정 화면에서 아무것도 바꾸지 말고 파란색 Deploy 버튼을 클릭합니다.

웹 플랫폼과 출력물의 완벽한 이원화(Dual-track) 설계 원칙
